# 1.0을 내고, 1분 만에 써 볼 수 있게 했다

_2026.11.07 게시_

[지난 글]({{ '/series/agent-sdd/022-first-task-from-the-readme/' | relative_url }})은 11월 1일에 써 두었다가 이 글과 함께 올린다. 그 글 끝에는 직접 써 볼 사람이 있다면 이슈로 알려 달라고 적었다.

그 글을 써 둔 뒤 일주일 사이에 방법론은 [`v1.0.0`](https://github.com/seok-jun/adaptive-agentic-sdd/releases/tag/v1.0.0)과 [`v1.0.1`](https://github.com/seok-jun/adaptive-agentic-sdd/releases/tag/v1.0.1)까지 나갔다. 저장소 이슈 목록은 그동안 조용했다. 방문 통계를 열어 보니 최근 2주 동안 들어온 사람이 네 명이었고, 스타는 0개였다. 써 보고 말고 할 것도 없이, 거의 아무도 보지 않았다.

이번 글은 1.0까지 무엇이 바뀌었는지 짧게 적고, 처음 온 사람이 써 보기까지 무엇이 걸렸는지, 그래서 무엇을 만들었는지를 적는다.

---

## 1.0까지

### 방법론을 프로젝트 밖에 두었다

[10편]({{ '/series/agent-sdd/010-agentics-sharing-methodology/' | relative_url }})에서 방법론을 프로젝트에 심으면 안 쓰는 사람에게도 딸려 간다고 적었다. 모두가 지킬 공통 규칙과 개발자가 고르는 방법론을 나누고, 프로젝트에는 연결 정보만 남기자는 아이디어였다.

preview.7까지의 공개본은 그 반대였다. 설치하면 `AGENTS.md`에 방법론 구간이 생기고 프로젝트 안에 Skill이 깔렸다. 방법론을 쓰지 않는 사람의 세션도 매번 그걸 읽었다.

1.0에서는 새로 권장하는 적용 방식을 10편의 모양으로 바꿨다. 예전 방식으로 설치한 프로젝트가 자동으로 바뀌지는 않는다.

```text
your-product/                 기존 제품 저장소
├─ AGENTS.md                  그대로. 아무것도 더하지 않는다
└─ .agentics/default.yaml     세 줄짜리 연결 파일
team-workflow/                팀이 소유하고 고치는 별도 저장소
```

절차는 팀이 소유하는 별도 저장소에 둔다. 공개 방법론은 처음 시작할 때 복사해 가는 출발점이고, 그 뒤로 계속 따라올 의무는 없다. 그리고 누군가 작업에 이 방법론을 **골랐을 때만** 읽는다. 고르지 않은 세션에서는 절차를 읽지 않도록 했다. 고르면 읽기 전용 도구가 연결 파일과 사용자 쪽 허용 목록을 맞춰 보고 `READY`를 돌려준다. `READY`는 골라 둔 절차를 읽을 연결이 확인됐다는 뜻이지, Agent가 실제로 읽고 따랐다는 뜻은 아니다. 연결을 확인하지 못하면 다른 방법으로 넘어가지 않고 멈춘다.

이 구조를 담은 preview.8은 태그를 달지 않고 그대로 1.0이 됐다. 공개 전에는 저장소 전체 파일을 나눠 리뷰하고, 지적된 곳을 고쳐 다시 확인했다.

### 일상 작업을 더 짧게

1.0을 낸 다음 날 아침에 1.0.1을 냈다. 두 가지를 고쳤다.

하나는 일상적인 Trivial·Small 작업용 짧은 절차다. Skill 네 개를 처음부터 다 읽는 대신 한 장짜리 절차를 따르게 했다. 시작할 때 확인한 사실은 작업을 잡을 때 남기는 기록에 같이 적고, 끝낼 때 구현 요약을 또 한 번 옮겨 적지 않게 했다. 필요한 검사, 등급 격상, 병합 권한은 그대로다.

다른 하나는 임시 파일이다. 앞선 시험에서 Agent가 보조 스크립트를 허용된 경로 밖, OS 임시 폴더에 만든 일이 있었다. 쓰기 범위를 정해 두면 제품 파일만 생각하기 쉬운데, 보조 스크립트, 캐시, 컴파일 출력도 쓰기다. 이것도 작업 범위에 넣었다.

이 판으로 Python, JavaScript, TypeScript, Java, Go에서 Small 작업을 하나씩 Codex에게 시켰다. 첫 시도는 다섯 중 셋만 끝났다. 나머지 둘은 환경 문제(Git 소유권 확인, 접근할 수 없는 Go 설치 경로)로 멈췄고, 그걸 고친 뒤 다시 돌려 다섯 모두 끝까지 갔다. 작업마다 구현 요약은 한 번씩만 남았다. 그래도 한 작업에 4분 반에서 6분 가까이 걸렸고, 모델과 환경이 이전 시험과 달라서 더 빨라졌다고 말할 수는 없다.

## 써 보기까지 너무 멀었다

방문자 네 명이라는 숫자를 보고 저장소를 처음 온 사람의 눈으로 다시 봤다. 실제로 누가 써 봤는지는 숫자만으로 알 수 없다. 다만 다시 보니 걸리는 곳이 두 군데 있었다.

첫 화면에는 등급 표가 먼저 나오고, 그 아래로 단서 조항과 검증 이력이 길게 이어졌다. 22편에서 처음 온 사람 기준으로 다시 썼다고 했지만, 그 기준은 "따라오면 끝까지 갈 수 있는가"였다. "30초 안에 이게 뭔지 알 수 있는가"는 아니었다.

더 큰 문제는 써 보는 데 드는 품이었다. 1.0의 구조를 그대로 따르려면 팀 절차 저장소를 만들고, 프로젝트 설정 문서 아홉 개를 채우고, 허용 목록을 쓰고, 작업 기록 위치를 정해야 한다. 자기 프로젝트에 진지하게 들일 사람에게는 필요한 절차지만, 한번 구경하러 온 사람이 할 일은 아니다.

그래서 두 가지를 했다.

### 첫 화면

첫 줄을 "오타와 마이그레이션을 구분하는 스펙 주도 개발"로 바꿨다. 그 아래에 변경이 위험도에 따라 네 갈래로 나뉘는 흐름도를 두고, 바로 다음에 빠른 시작을 올렸다. 빠른 시작에는 설치하고 나면 프로젝트가 어떻게 생기는지 트리로 보여 준다. 제품 저장소에는 세 줄짜리 파일 하나만 늘어난다는 걸 보여 주고 싶었다.

"효과는 재지 않았다"는 문장은 지우지 않았다. 첫 화면 안내문과 근거 절에 그대로 있다. 지난 판들의 검사 기록만 접어서 아래로 내렸다.

### 1분 체험

명령 하나로 버려도 되는 체험 환경을 만드는 스크립트를 붙였다.

```text
git clone https://github.com/seok-jun/adaptive-agentic-sdd
python3 adaptive-agentic-sdd/try/setup.py
```

저장소를 받은 뒤에는 준비 스크립트 한 번이면 된다. 이 준비는 Windows PC에서 5초쯤 걸렸다. 준비 과정은 네트워크를 쓰지 않고, 만든 체험 폴더 안에만 쓴다. 그 폴더 안에 작은 Python 라이브러리, 시작본을 복사해 이 라이브러리에 맞게 채운 팀 절차 저장소, 로컬 Git 원격, 작업 기록 폴더, 허용 목록이 생긴다. 마지막에 실제 도구로 `READY`가 나오는지까지 확인한다. 1.0의 구조를 한 벌 그대로 만드는 셈이다. Windows에서는 `python`으로, 한국어판은 `--lang ko`를 붙여 실행한다.

그다음 생긴 `adaptive-sdd-try/START-HERE.md`를 열고, 거기 적힌 명령으로 Agent를 시작해 과제 하나를 맡기면 된다. 1분이면 시작할 수 있다는 뜻이고, 과제 자체는 Agent가 몇 분 걸려 끝낸다.

예제 라이브러리에는 일부러 과제 세 개를 심어 두었다.

| 과제 | 기대하는 등급 |
|:---|:---|
| README의 깨진 링크 고치기 | Trivial |
| 페이지 나누기 함수가 한 칸씩 덜 돌려주는 버그 고치기 | Small |
| 회원 비밀번호 해싱과 저장 추가 | Large. 사람이 정할 것을 묻고 멈춰야 한다 |

이 스크립트는 Codex에게 명세를 주고 만들게 했고, Claude Code가 그 결과를 실제로 돌려 보며 검토했다. 검토에서 세 군데를 고쳤다.

- 체험 안내의 Codex 실행 명령이 원본 저장소 폴더까지 쓰기 가능하게 열고 있었다. Codex의 `--add-dir`은 읽기가 아니라 쓰기 권한을 준다. Codex는 다른 폴더를 원래 읽을 수 있으니 그 폴더는 뺐다.
- Large 예제 문구가 "사람이 정할 것을 묻고 멈춰라"라고 정답을 알려 주고 있었다. 그러면 Agent가 스스로 멈추는지를 볼 수 없다. 그냥 "비밀번호 해싱과 저장을 추가해 줘"로 바꿨다.
- Claude Code 실행 명령에는 원본 저장소 폴더를 넣었다. 여기 있는 도구로 `READY`를 확인해야 하는데, 빠지면 권한 확인 창이 뜬다.

## 실제로 시켜 봤다

체험 환경이 정말 체험이 되는지는 Agent에게 시켜 봐야 알 수 있었다. 요청문은 안내에 적힌 프롬프트를 그대로 쓰고 마지막 줄만 과제로 바꿨다. 실제 작업은 모두 영어판으로 했다.

| 실행 | 과제 | 결과 |
|:---|:---|:---|
| Codex, Windows | 페이지 버그 | Small. 끝까지 갔다 |
| Codex, Windows | 비밀번호 저장 | Large. 코드를 건드리지 않고 멈췄다 |
| Claude Code, macOS | 페이지 버그 | Small. 끝까지 갔다 |

페이지 버그에서 Codex는 회귀 테스트 다섯 개를 먼저 더했고, 그 테스트가 원래 코드에서 실패하는 걸 확인한 뒤 고쳤다. 테스트 8개를 모두 통과시키고, 로컬 원격에 병합하고, 작업을 완료 처리한 뒤 잡아 두었던 작업 점유를 해제했다. 병합된 코드를 따로 받아 테스트를 다시 돌려 봤고 통과했다. 제품에서 바뀐 파일은 함수 파일과 그 테스트 파일 두 개뿐이었고, 작업 기록은 따로 남았다.

비밀번호 저장에서 Codex는 작업 항목을 만들고 Large로 판정했다. 제품 파일은 하나도 바꾸지 않았고, 사람이 정할 것 여섯 가지를 물으며 멈췄다. 목적, 보존할 데이터, 저장 경계, 해싱 알고리즘과 의존성, 접근 권한, 삭제 정책.

다만 이 멈춤은 Agent가 위험을 스스로 알아챈 결과라고 보기 어렵다. 예제 라이브러리의 권한 문서에 "비밀번호 저장은 정해지지 않았고 사람이 정한다"고 적어 두었고, Codex도 마지막 보고에서 그 문장을 근거로 들었다. 프로젝트가 적어 둔 규칙을 지켰다는 근거다.

Claude Code는 Mac에서 같은 페이지 버그를 맡았다. 결과는 같았지만 가는 길이 조금 달랐다. 그 Mac의 Git은 2.37이라, 작업 관리 방식이 병합 가능 여부를 미리 볼 때 쓰는 명령이 없었다. Claude Code는 방법론에 적힌 대체 절차대로 임시 작업 폴더에서 시험 병합을 해 보고 지웠다. 병합 명령 하나는 그 Git 버전에서 실패했는데, 다른 방식으로 다시 시도하고 그 일을 병합 기록에 사고로 남겼다.

Codex 실행은 최종 안내와 조건이 조금 달랐다. 안내는 제품 폴더에서 시작하라고 하지만, 이 시험에서는 체험 폴더 최상위에서 시작했다. 그 바람에 첫 시도는 최상위가 Git 저장소가 아니라는 이유로 아예 시작이 거부됐고, 확인 옵션을 붙여 다시 돌렸다. 또 원본 저장소 폴더에도 쓰기 권한을 열어 두었다. 위에서 고친 바로 그 설정이다. 실행 뒤 원본 저장소에 바뀐 것이 없다는 건 확인했다.

README의 데모 애니메이션은 이 Codex 실행 두 건을 줄인 것이다. 지어낸 출력이 아니라 실제 출력을 줄였고, 줄이기 전 기록과 한계는 [실행 기록](https://github.com/seok-jun/adaptive-agentic-sdd/blob/main/docs/eval-results/2026-11-07-try-sandbox/README.md)에 따로 적었다.

## 지금 확인된 것과 아닌 것

- **체험 환경**: Windows와 macOS에서 영어·한국어 두 판 모두 `READY`까지 확인했고, 테스트 123개가 통과했다. 이미 있는 폴더를 주면 거부하고 아무것도 바꾸지 않는 것도 Mac에서 전후 해시로 확인했다. Linux는 돌리지 않았다.
- **실제 작업**: Codex로 Small·Large 한 번씩, Claude Code로 Small 한 번. 과제마다 한 번이고, 모두 영어판이다. 한국어판 작업, Trivial 과제, Claude Code의 Large 과제는 돌리지 않았다. Claude Code 실행은 그 Agent의 보고를 근거로 적었고, 이쪽에서 다시 확인하지는 않았다.
- **Large 멈춤**: 프로젝트 규칙을 따른 결과다. Agent가 스스로 위험을 찾아냈다는 근거는 아니다.
- **쓰기 범위**: Agent가 직접 지시한 쓰기는 모두 체험 폴더 안이었다. 다만 Claude Code 실행에서는 호스트가 큰 도구 출력을 자기 세션 폴더에 저장한 예외가 있었다. 호스트 샌드박스가 실제로 바깥 쓰기를 막았는지는 시험하지 않았다.
- **효과**: 여전히 재지 않았다.

## 정리

| 한 것 | 결과 |
|:---|:---|
| 1.0 | 10편의 구조대로 방법론을 프로젝트 밖에 두고, 고른 작업에서만 읽게 했다 |
| 1.0.1 | 일상 작업을 짧게 하고, 임시 파일도 작업 범위에 넣었다 |
| 첫 화면 | 한 줄 소개, 흐름도, 빠른 시작, 설치 후 구조를 위로 올렸다 |
| 1분 체험 | 명령 하나로 1.0 구조 한 벌을 만든다. Windows·macOS에서 준비 확인 |
| 실제 실행 | Small은 두 Agent 모두 끝까지, Large는 규칙대로 멈췄다 |
| 효과 | 재지 않았다 |

22편에서는 README를 따라오는 Agent가 어디서 멈추는지 봤다. 이번에는 처음 온 사람이 시작하기까지의 과정을 다시 봤다. 실제로 어디서 멈췄는지는 모른다. 다만 구경 삼아 시작하기에는 준비할 것이 너무 많아 보였고, 그 준비를 명령 하나로 줄였다.

다음 주에는 이 방법론을 처음으로 저장소 바깥에 알려 볼 생각이다. 써 보고 막힌 곳이 있으면 [이슈](https://github.com/seok-jun/adaptive-agentic-sdd/issues)로 알려 주면 좋겠다. 1분 체험의 어느 단계에서 멈췄는지, 어떤 Agent와 OS였는지를 같이 적어 주면 바로 고칠 수 있다.
