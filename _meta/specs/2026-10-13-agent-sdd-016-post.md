- 15편의 진단 과제 결과는 "A는 예외·재시도·취소, B는 재시도·취소 경로를 놓쳤다"로 적혀 있다. 이후 개발 저장소의 재검토(2026-10-10)에서 이 판정의 근거가 검사별로 다르게 평가됐지만, 공개 글에는 반영되지 않았다.

## TO-BE

- 연재 16편 `열세 번 돌리고, 판정을 다시 봤다`(가제)를 게시한다. 게시일은 게시 시점에 확정한다.
- 16편은 짧은 실험 노트로 쓴다. 15편 이후 한 쌍을 더 돌린 결과와 15편 판정의 재검토만 다룬다. 사례 조사와 0009 방향은 17편의 본론으로 넘긴다(2026-10-13 작성자 결정. 처음 초안은 8단계 흐름이었으나 실험 일지에 가까워 압축했다).
- 글의 흐름:
  1. **한 쌍을 더 돌렸다.** 15편 마지막 문장을 받아, 아직 평가에 쓰지 않은 과제로 A/B 한 쌍을 돌렸다. A는 편집 전 순서 있는 변경 목록 의무, B는 의무 없음. 모델은 GPT-5.6 Sol / medium, 모델 작업 시간 각 600초. 결과는 양쪽 모두 숨긴 핵심 요구 4개 통과, 같은 기존 테스트 12개 실패로 전체 기준 미충족이며 효과 결론은 없다. 원인은 주로 실험 조건이다(채점 한 번에 약 958초인데 모델 시간은 600초. 두 후보 모두 기존 테스트 실패를 보지 못함. 600초 안에 다 돌리기 어려웠다는 것은 기록상 추정). B도 목록 없이 순서를 먼저 설명했다.
  2. **지난 글의 판정을 다시 봤다.** 숨긴 검사 결과는 재현됐지만, 요구사항 기준으로 다시 보니 취소는 어겼다고 보기 어려워졌고, 재시도는 해석에 달렸고(정답 코드도 일부 경우 상한을 지키지 못함), 예외(A)는 그대로 실패다. 15편 본문은 고치지 않고 이 글에서 고쳐 읽는다. A의 목록에 실패한 부분이 처음부터 없었다는 점과, 채점하던 검사도 정답 코드의 내부 모양을 보던 것이 섞여 있었다는 점을 남긴다.
  3. **여기까지.** 누적 13회(15편 11회 + 이번 2회), 효과 결론 없음, 예산 소진, 이어갈지는 미정. "검사를 통과한 것과 요구를 지킨 것이 다르다"는 유형이 실제 사례 조사에서도 가장 많았다는 한 문장으로 17편에 넘긴다.
- 본문 SVG 도식 한 장(`grader-recheck.svg`: 15편 진단 과제의 세 검사가 다시 본 뒤 "어겼다고 보기 어려워짐 / 해석에 달림 / 그대로 실패"로 갈리는 모습)과 섬네일 한 장을 넣고, front matter `image`에 섬네일을 연결한다.
- 연재 목록, 홈의 시리즈 카드, 저장소 소개에 16편과 편수(16편)를 반영한다.

## 제약 조건

- 공개 글이 비공개 저장소 링크에 의존하지 않도록 판정표와 결과 수치를 본문에 직접 싣는다. 제품 과제의 내용은 15편 수준의 추상도를 유지하고, 제품 저장소 이름·이슈 번호·경로는 쓰지 않는다.
- 수치는 개발 저장소의 기록 그대로 쓴다. "600초 안에 전체 검사가 불가능했다"는 기록이 추정으로 적은 것이므로 추정으로 쓴다.
- 해석의 경계를 지킨다.
  - 양쪽이 같은 실패를 보였다고 동등성이나 효과·역효과를 주장하지 않는다.
  - detekt 지적 수의 차이(4 대 1)로 우열을 말하지 않는다.
  - 예외 검사에서 A의 위반이 남은 것을 목록 작성의 역효과로 해석하지 않는다.
  - 이번 쌍(GPT-5.6 Sol / medium)과 15편 진단 과제(GPT-6.1 Sol / xhigh)를 비교해 모델 차이를 주장하지 않는다.
  - 회귀 실패를 실제 사용자 데이터 손상으로 확대하지 않는다.
- 과제 선정의 한계를 숨기지 않는다. 편의로 고른 표본 하나이고, 과거에 사전 검토 이력이 있었으며, 준비자는 당시 해결 코드를 안다. A→B 순서는 고정이고 조건당 1회다.
- 비교를 "접었다"고 쓰지 않는다. 기록상 상태는 추가 예산 없음, 새 비교·실행기 수정 미승인, 사람 판단 대기다.
- 15편 본문은 고치지 않는다. 정정은 16편 본문에서만 한다.
- 결정 0008(이슈 replay 평가)은 미채택이다. 판정표는 15편과 같이 "검토 중이던 계획에 미리 적어둔 것"으로 쓴다.
- 도식과 섬네일은 12~15편과 같은 팔레트·글꼴 스택·구성을 따른다. mermaid를 쓰지 않는다.
- 테마, `_config.yml`, 검색 설정, Pages 워크플로는 변경하지 않는다.
