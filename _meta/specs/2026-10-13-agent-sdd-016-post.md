# Agent SDD 연재 16편 (마지막 비교와 판정 재검토) 게시 명세

## AS-IS

- Agent SDD 연재는 15편까지 게시되어 있고, 홈·연재 목록·저장소 소개의 편수도 15편이다.
- 15편은 "다음에 잰다면 아직 쓰지 않은 다른 작업과 새 한도를 먼저 정해야 한다"로 끝난다. 그 뒤의 실험과 판단을 다룬 글은 없다.
- 15편의 진단 과제 결과는 "A는 예외·재시도·취소, B는 재시도·취소 경로를 놓쳤다"로 적혀 있다. 이후 개발 저장소의 재검토(2026-10-10)에서 이 판정의 근거가 검사별로 다르게 평가됐지만, 공개 글에는 반영되지 않았다.
- 근거 기록은 비공개 개발 저장소에 있다.

## TO-BE

- 연재 16편 `열세 번 돌리고, 채점표부터 다시 봤다`(가제)를 게시한다. 게시일은 게시 시점에 확정한다.
- 글의 흐름:
  1. **도입.** 15편 마지막 문장을 받아, 아직 평가에 쓰지 않은 과제 하나와 새 한도를 먼저 정했다고 연다.
  2. **조건 고정.** A는 편집 전 순서 있는 변경 목록 의무, B는 의무 없음(자발적 계획은 허용). 모델은 GPT-5.6 Sol / medium으로, 15편 진단 과제(GPT-6.1 Sol / xhigh)와 다르다. 모델 작업 시간은 각 600초, 회차 전체 1,800초, 합계 3,600초다. 전체 채점에만 약 958초가 걸려 모델 시간을 900초에서 600초로 줄였고, 이 줄인 시간이 해석 조건이 된다는 점을 미리 밝힌다. 실제 호출 전에 오프라인 리허설을 끝까지 돌리고 채점기가 핵심 누락을 잡는지 먼저 확인했다.
  3. **결과.** 양쪽 모두 모델 작업이 600초 한도에서 끝났고 완료 응답은 없었다. 숨긴 핵심 요구 4개는 양쪽 모두 통과했지만, 같은 검사에서 기존 회귀 실패가 12개씩(version 기대값 미갱신 7, 이전 fixture에 없는 테이블 5) 나왔다. detekt 긴 줄 지적은 A 4개, B 1개다. 양쪽 모두 전체 품질 기준 미충족이며, 미리 적어둔 판정에 따라 효과 결론은 없다.
  4. **비교 변수의 정체.** B도 편집 전에 산문으로 작업 순서를 설명했다. 이 비교는 계획의 유무가 아니라 목록 의무의 유무였다.
  5. **실패 원인 재분류.** 이번 쌍의 실패는 주로 실험 조건이다. 두 후보 모두 기존 검사의 실패를 한 번도 보지 못했고, 600초 안에 전체 검사를 끝내기는 어려웠던 것으로 보인다(기록상 추정). 기존 검사를 찾아보지 않은 검색 범위 부족도 있었다. 이 조건으로는 보조 효과 비교를 하지 않기로 했다.
  6. **15편 판정의 재검토와 정정.** 숨긴 검사 5개의 결과는 당시와 실패값까지 재현됐다. 그러나 검사가 무엇을 보는지 다시 확인하니 취소 검사는 내부 표시 하나의 차이라 요구 위반의 근거가 약해졌고, 재시도 검사는 요구 해석에 달렸으며(참조 구현도 일부 형태에서 상한을 지키지 못함), 예외 검사의 위반(목록 의무가 있던 A)은 남는다. 15편 본문은 고치지 않고 이 글에서 정정한다. "후보뿐 아니라 채점기도 채점해야 했다"를 핵심 문장으로 둔다.
  7. **멈춘 이유.** 실제 평가 시도는 누적 13회(15편의 11회 + 이번 2회)이고 효과 결론은 없다. 추가 예산은 없으며 새 비교를 할지는 사람 판단 대기 상태다. 효과를 확인하기 전에 실험 장치가 커지는 것을 경계한 0009의 문제의식으로 잇는다.
  8. **마무리.** 확인한 것 / 아직 모르는 것 표와, 실험 비교 대신 실제 사건을 먼저 본 다음 편(사례 조사)으로의 연결.
- 본문 SVG 도식 두 장과 섬네일 한 장을 넣고, front matter `image`에 섬네일을 연결한다.
  - `time-budget.svg`: 모델 작업 600초와 채점 약 958초, 회차 1,800초의 관계. 모델이 기존 검사 실패를 보기 전에 시간이 끝났다는 점.
  - `grader-recheck.svg`: 15편 진단 과제의 세 검사(취소·재시도·예외)가 재검토 뒤 "근거 약해짐 / 해석에 달림 / 위반 남음"으로 갈리는 모습.
- 연재 목록, 홈의 시리즈 카드, 저장소 소개에 16편과 편수(16편)를 반영한다.

## 제약 조건

- 공개 글이 비공개 저장소 링크에 의존하지 않도록 판정표와 결과 수치를 본문에 직접 싣는다. 제품 과제의 내용은 15편 수준의 추상도를 유지하고, 제품 저장소 이름·이슈 번호·경로는 쓰지 않는다.
- 수치는 개발 저장소의 기록 그대로 쓴다. "600초 안에 전체 검사가 불가능했다"는 기록이 추정으로 적은 것이므로 추정으로 쓴다.
- 해석의 경계를 지킨다.
  - 양쪽이 같은 실패를 보였다고 동등성이나 효과·역효과를 주장하지 않는다.
  - detekt 지적 수의 차이(4 대 1)로 우열을 말하지 않는다.
  - 예외 검사에서 A의 위반이 남은 것을 목록 작성의 역효과로 해석하지 않는다.
  - 이번 쌍(GPT-5.6 Sol / medium)과 15편 진단 과제(GPT-6.1 Sol / xhigh)를 비교해 모델 차이를 주장하지 않는다.
  - 회귀 실패를 실제 사용자 데이터 손상으로 확대하지 않는다.
- 과제 선정의 한계를 숨기지 않는다. 편의로 고른 표본 하나이고, 과거에 사전 검토 이력이 있었으며, 준비자는 당시 해결 코드를 안다. A→B 순서는 고정이고 조건당 1회다.
- 비교를 "접었다"고 쓰지 않는다. 기록상 상태는 추가 예산 없음, 새 비교·실행기 수정 미승인, 사람 판단 대기다.
- 15편 본문은 고치지 않는다. 정정은 16편 본문에서만 한다.
- 결정 0008(이슈 replay 평가)은 미채택이다. 판정표는 15편과 같이 "검토 중이던 계획에 미리 적어둔 것"으로 쓴다.
- 도식과 섬네일은 12~15편과 같은 팔레트·글꼴 스택·구성을 따른다. mermaid를 쓰지 않는다.
- 테마, `_config.yml`, 검색 설정, Pages 워크플로는 변경하지 않는다.
