# 켄트 백 글 7절 관점 수정

## AS-IS

- 6절 말미와 7절은 변경 가능성을 점검하고 작업 메모에 기록하는 적용 절차를 제안한다.
- 기록을 보관하는 것과 다음 에이전트의 실제 판단에 쓰는 것을 구분하지 않아, 절차의 효과를 과장할 수 있다.

## TO-BE

- 백의 반복 개발·학습에 관한 문제의식에서 시작해, 글쓴이가 AI 협업에 대입하며 갖게 된 질문으로 7절을 다시 쓴다.
- 기획자와 개발자의 발견·수정·보류 합의를 예로 들고, 다음 에이전트에게 그 맥락이 이어지는 문제를 설명한다.
- 작업 메모 표와 항목 추가 제안은 제거한다. 완성된 방법론이나 효과가 검증된 해결책으로 제시하지 않는다.
- 도식은 보류한 합의와 다음 작업의 판단 사이에 필요한 연결을 보여준다.

## 제약 조건

- 기존 강연 출처와 공개 v0.2 비교 기준을 유지한다.
- 에이전트 간 판단 인계를 백의 직접 제안으로 돌리지 않는다. 글쓴이의 생각으로 자연스럽게 연결한다.
- 사람의 기억이 완벽하다거나 기록만으로 AI가 맥락을 이어간다고 쓰지 않는다.
- 새로운 AI 운영 규칙이나 자동 검색·이슈 관리 기능을 저장소에 도입하지 않는다.

## 검증 기준

- 기록의 보관과 실제 재검토의 차이가 본문·도식에서 일치한다.
- SVG XML 파싱, 실제 렌더링의 글자·화살표·겹침, 내부 링크와 이미지 경로를 확인한다.
- `git diff --check` 및 GitHub Pages의 Jekyll 빌드를 확인하고 공개 본문의 변경을 확인한다.

## 후속 검토

- 관련 작업에 보류된 판단을 누가 연결할지, 재검토 조건을 어떻게 정할지, 운영 비용 대비 효과가 있는지는 방법론 연구 과제로 남긴다. 이번 글에서는 새 절차를 확정하지 않는다.
